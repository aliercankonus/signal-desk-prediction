## Reviewed boundary

A separately reviewed, private UTF-8 JSON file (regular file, owned by the invoking user, owner-only permissions, at most 2048 bytes) is required for every `once` path, including direct library use. The bridge opens it without following a final-component symlink, validates the opened descriptor, reads at most 2049 bytes and rejects size/content instability. Constructing a `Policy` alone cannot authorize dispatch. It contains exactly these keys, with no extra fields or duplicate keys:

```json
{"repo":"aliercankonus/signal-desk-prediction","issue":101,"body_digest":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","base":"bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb","branch":"review-task-101"}
```

**This is a synthetic example, not an authorization to run.** The eventual manager-created smoke issue must have its own actual number, reviewed body and exact UTF-8 SHA-256, real immutable starting commit object, and reviewed unused task branch (never `main`, `master` or the legacy `issue-22-bridge`). The record cannot specify commands, credentials, URL, prompt, state or worktree. The fixed repository is validated, the issue is read as open with exact body digest both before progress and before dispatch, the source origin must match, the base must be a local commit object, and the reviewed branch must not exist. The state directory is outside the checkout and separate from the authorization file; generated worktrees are under its private `worktrees/` subdirectory. Do not reuse a journal from another task, silently clear a blocked run, or reuse the legacy issue #22 identity.

The **installed runner revision** is the reviewed bridge code loaded from `REPO_DIR/src` after its future merge; it is not the record's `base`. The `base` is the task worktree's immutable starting commit, and the target `main` tip is a separate moving observation. Confirm the installed runner's exact reviewed SHA and Python import path independently before any later real invocation; changing `base` does not update runner code. No CLI issue/base/branch/command/prompt override exists. The CLI still requires `--execute-hermes` explicitly and does not discover issues or run a scheduler.

## Private test-interpreter execution context (issue #28 proposal)

The **task authorization** above remains independently reviewed and unchanged. A separate owner-private (`0600`, owner-private parent) UTF-8 JSON context file outside the source checkout, state and authorization file is additionally required for any future `once`. It has exactly `test_python` (absolute path to an existing private venv interpreter), `requirements_sha256` (SHA-256 of that runner checkout's bounded `requirements.txt`), `runner_commit` (the exact installed runner HEAD, **not** necessarily the task start), `python_version` and `pytest_version`. The record cannot supply commands or choose an issue/worktree. This is an example shape, **not an authorization**:

```json
{"test_python":"/private/venvs/reviewed/bin/python","requirements_sha256":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","runner_commit":"bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb","python_version":"3.14.9","pytest_version":"8.3.3"}
```

Before any public progress or child dispatch, the runner reads this file with a 2048-byte no-follow, owner/mode, stability and exact-field check. It verifies the current runner HEAD, bounded requirements hash and pinned pytest version, a private existing venv, the explicit interpreter's isolated Python/pytest import/version and `python -m pip check`, each with time/output limits. The installed terminal backend must be confirmed `local`; another backend is rejected until an independently established access path is reviewed. The child still checks actual terminal-side accessibility **before editing**. No dependency install or mount is performed.

After creating the task worktree, the runner writes one no-overwrite `0600` runtime context in the private state containing that exact worktree and approved interpreter. The `0600` child prompt prepends trusted, shell-quoted explicit interpreter and worktree instructions before the frozen issue prose. It tells the child to stop if inaccessible and to invoke the interpreter by absolute path, without custom exported variables, bare `python` or login-shell `PATH`. The issue body is untrusted task data and cannot supply the interpreter or shell command; controlled status comments never include private context paths. This is a pre-dispatch/local-tool access fence, not a sandbox, distributed lease, or guarantee that an LLM will comply.

**Measured issue #27 evidence:** its supervisor exported `SIGNAL_DESK_TEST_PYTHON`, but the child's terminal reported it unset and the child stopped before editing. Read-only installed configuration showed `terminal.backend=local`, `terminal.env_passthrough=[]`, and a persistent local shell. The bridge spawns Hermes as a subprocess; installed Hermes local terminal code constructs a separate tool environment and captures a login-shell snapshot. The exact point where issue #27's variable disappeared remains **unproven**; neither `env_passthrough=[]` alone nor parent `Popen` inheritance establishes it. One separately authorized read-only issue #28 diagnostic child, run with bounded noninteractive flags and private bounded capture, observed the explicit approved interpreter in the actual terminal tool: Python 3.14.9, pytest 8.3.3, importable; it exited zero without modifying the probe area. This proves context access on this local backend only, **not** a GitHub-to-PR smoke or Python 3.12 CI parity.

The journal records the canonical authorization digest, issue, body digest, pinned commit, reviewed branch, run ID and worktree path before public progress or child launch. It is a one-run durable record, not an exactly-once receipt: lock scope is only one state directory on one machine. Interrupted, ambiguous or publication-failed attempts remain blocked; no hidden retry. Duplicate `once` on a review-ready row rechecks both the open issue's exact body digest and the draft PR; a changed, closed or unavailable issue durably blocks rather than reporting stale readiness. `doctor` is local read-only; `reconcile` is read-only and compares status receipts, draft PR target/repo, pinned ancestry, exact head and exact-head CI. Unknown/pending CI is reported, not called green. A later `main` advance alone does not change the immutable starting commit. Public statuses contain only allowlisted identities/results, never issue prose, agent output, private paths or credentials.

## Proposed supervisor-owned draft publication (issue #32)

The child receives trusted instructions to finish **only** the authorized edits, tests, commit and push on the precreated task branch. It must not require `gh`, create a PR, run another bridge, or supply a PR URL/body. The runner then checks that the child worktree is on the reviewed branch, clean, has a new commit with a changed tree descended from the immutable task start, and that the pushed remote branch ref equals the local HEAD. It rechecks the fixed origin, frozen issue and private authorization before any PR effect. A failed check blocks without a PR POST; child prose is not a result receipt. The commit and remote-ref checks do not independently prove that the child ran tests; review the actual child/test evidence and exact-head CI separately.

The fixed-repository `GitHubREST` adapter first checks the reviewed remote branch head and inspects **all** candidate PR states for that branch. A single existing open draft is reused only after exact head, controlled title/body with `Refs #<authorized issue>`, repository, branch, target `main`, pinned ancestry and exact-head CI readback. Conflicting, closed, non-draft, wrong-head, or multiple candidates block. With no candidate, the bridge durably records one private PR-create intent, rechecks the live issue and private authorization after discovery, then makes its sole `POST /repos/<fixed-repo>/pulls` with a fixed title/body, target `main`, reviewed branch and `draft=true`; it records the response number and verified readback separately. A timeout, lost response, conflicting readback or crash remains **blocked** with its intent/response stage inspectable through read-only doctor/reconcile. Never automatically POST again to resolve ambiguity. The approved development credential helper is used by the existing REST boundary; no new CLI, credential scope, mount or host permission is needed. A moving `main` tip is observed separately from the immutable task start. This local lock and journal are not a distributed exactly-once protocol or an agent sandbox.
