## Minimal v1 implementation
- GitHub issue is the shared task and status location; linked draft PR is the deliverable. Do not create another trading engine or change ledger semantics.
- One explicitly configured repository, one approved issue at a time, one Hermes worker instance. Start with this issue as the explicit allowlisted bootstrap task; no automatic discovery/execution of arbitrary issues or comments.
- Task authorization must bind issue number, a frozen task-body digest/revision and a pinned code base. Edits invalidate an unstarted authorization. Issue content, comments and labels do not independently grant shell, credential, merge or deployment authority.
- Use a local process lock and a durable bounded task/run journal outside git. Document that this guarantees exclusion only for this single worker/state directory; labels or check-then-write GitHub comments are not atomic distributed claims.
- Persist run identity before agent invocation; record branch/worktree and progress. If restart leaves an ambiguous invocation or push result, inspect/reconcile it and block redispatch until resolved. Do not promise exactly-once external execution.
- Use separate worktrees; never reset, clean, stash or overwrite an existing checkout. Bound work duration, retries, child-process lifetime, output size and retained logs. Interruption/timeout must terminate the process group and retain a recoverable task state.
- Publish concise, redacted status to the authorized issue: queued/running/blocked/review-ready, run ID, pinned base, draft PR URL, exact head and exact-head CI result. Keep secrets, private config and host logs out of GitHub.
- Keep merge, deployment, privileged host operations, collector startup and operator-data migration outside the worker's authorization. Use existing development credentials only within their actual permissions; do not claim logical restrictions revoke token capabilities.
- Provide a read-only doctor/dry-run and a bounded once mode. Do not enable a persistent poller or schedule in this PR. Provide a separate explicit opt-in setup/stop/recovery procedure after review.
- Keep documentation and task templates in English. Record current deployment remains unchanged.
