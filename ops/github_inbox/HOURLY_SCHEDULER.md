# Dormant hourly #41/#45 inbox scheduler — review only

`hourly_scheduler.py` is a **non-LLM process** that waits for the next `:30` in `Europe/Amsterdam`, then calls only the existing `Inbox.tick → production_executor → BridgeQueue → Bridge.once` path. It neither creates authority nor reenrolls. An empty or disabled feed calls no child/model/provider. `Inbox` still owns the signed-grant check, frozen #43 task scope, persistent cursor/instruction digest, claim-before-launch, queue mapping, receipts and its per-tick lock. A separate private `scheduler.lock` excludes a second scheduler process for its entire lifetime, including a long tick. A new scheduler process never clears a prior claim; an active, blocked, completed or uncertain claim prevents another child. A second process fails before constructing a GitHub client. This does **not** convert one frozen #43 authorization into arbitrary future work: a new task requires separately reviewed authority and enrollment.

The clock uses IANA `Europe/Amsterdam`, not a fixed UTC offset. At the spring transition the nonexistent 02:30 is skipped; at the autumn transition both occurrences of 02:30 are possible distinct UTC slots, with Inbox's persistent claim/dedup fencing any repeat instruction. The scheduler sleeps until a real slot and never catches up missed slots after a clock jump or restart outside the five-minute window. A tick has a 3300-second signal deadline; its synchronous execution prevents overlap and a tick lasting more than an hour skips the missed slot. The Bridge's own bounded child/cleanup and Inbox's fsynced claim remain authoritative. An abrupt process death cannot write a final receipt: a pre-effect read has no claim, while any already fsynced claim remains uncertain/blocked on later polling. A 429 honors Inbox's bounded `next_poll`; no automatic redispatch or quota-reset guess is introduced. Unknown exceptions stop the scheduler for operator read-only reconciliation. No model call is spent on a quiet GitHub poll.
